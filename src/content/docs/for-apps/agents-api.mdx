The **Agents API** lets your application's server call an AptiveAI
[agent](/concepts/agents) the way it would call a model. It is
**OpenAI-compatible**: any client that speaks OpenAI's chat completions works,
with two changes — AptiveAI's address and an AptiveAI key — and the `model` you
send is the **agent's id**.

What the agent brings that a bare model does not:

- **Its instructions and its model**, configured in AptiveAI Agents. Change
  either there, and every call uses the change; nothing in your application
  needs a release.
- **Its connector tools**, which run on AptiveAI's side inside your request —
  the agent can look things up in your systems before it answers.
- **Your own tools**, which you send with the request as usual. AptiveAI never
  runs them: when the agent calls one, the call comes back to you.

Every call is paid from your enterprise wallet, and the response says what it
was charged.

## API keys

An **owner of your enterprise** creates keys in AptiveAI Agents, under
**Settings → API keys**.

<Steps>

1. Press **New key**.
2. Give it a **Name** that says what it is for — only you see it.
3. Under **Agents**, choose the agents this key may call: at least one.
   Private and standalone agents are not listed.
4. Under **Services**, choose **Agents API**.
5. Leave **Keep conversations** off unless you need to read conversations
   later ([What is stored](#what-is-stored)).
6. Press **Create key**, then **Copy key**. The key starts with `aak_` and **is
   not shown again**: store it in your server's secret store.

</Steps>

A key carries the full authority of its agents' connectors, so it belongs on
your server only — never in a browser, a mobile app or a repository. Edit a
key to change its name, agents, services or **Keep conversations**; the secret
itself never changes. **Revoke** is immediate and permanent: anything calling
with the key stops working at once. Make a new key instead of reviving one.

The key's dialog also lists, under **Tools not offered over the API**, each
connector tool of its agents that a call cannot use, and why:

| Reason | What it means |
|---|---|
| *Needs a computer, which an API call does not have.* | Browser tools, browser workflows and anything else that needs the agent's computer |
| *Its sign-in is not shared with the agent.* | An API call has no person to sign in for. Only connectors set to **Use my connection** under **Who signs in** in the agent's builder are offered — see [Agents](/concepts/agents) |
| *Messaging cannot be sent from an API call.* | [AptiveAI Messaging](/concepts/messaging) is not available over the API |

## The request

```http
POST https://console.aptiveai.io/api/v1/chat/completions
Authorization: Bearer aak_…
Content-Type: application/json
```

The body is an OpenAI chat completions body. `model` is the **agent's id**:
the last part of the agent's address when you open it in AptiveAI Agents
(`https://console.aptiveai.io/agents/<id>`). The agent's own model is always
used; there is no way to choose another one from the request.

| Field | What happens |
|---|---|
| `model` | The agent's id. It must be one of the key's agents, not deleted and not private; otherwise `404 agent_not_found` — the same answer whether the agent does not exist or is not yours |
| `messages` | Roles `system`, `user`, `assistant` and `tool`; `developer` is treated as `system`. **Text only**: an image or audio part is `400 unsupported_content` |
| `tools` | Your tools, `type: "function"` only, with names of letters, digits, `_` and `-`, up to 64 characters. A name that is also one of the agent's tools is `400 tool_name_conflict` |
| `max_tokens`, `max_completion_tokens` | The most each model turn may write, up to 32,000 tokens (also the default) |
| `stream` | Supported — see [Streaming](#streaming) |
| `temperature`, `stop` | Checked (`temperature` from 0 to 2; `stop` up to 4 strings) but **not applied** |
| `tool_choice`, `stream_options` and anything else | Accepted and ignored, never an error, so a stock client works |

What the agent's model sees as its instructions: a short fixed note that it is
answering an application through the API, with no person to ask and no
computer; then the agent's own instructions; then your `system` messages, in
order.

The API is **stateless**. Your application keeps the conversation and sends it
whole each time.

## Two kinds of tools

| | The agent's tools | Your tools |
|---|---|---|
| What they are | The agent's connector tools that need no computer and whose sign-in is shared with the agent | The `tools` in your request |
| Who runs them | AptiveAI, on its side, inside your request | You |
| Approvals | None: over the API every call is approved | Yours to decide |
| What you get back | Their results, in `aptiveai.messages` | The calls, in `choices[0].message.tool_calls` |

When the model calls one of the agent's tools, AptiveAI runs it and the model
carries on. When it calls one of yours, the request ends and the call comes
back to you with `finish_reason: "tool_calls"`; run it and call again with its
result as a `tool` message. A turn that calls both runs the agent's first, then
returns yours. A tool of the agent's that fails is a result the model reads and
answers from, never an HTTP error.

### Keeping the agent's tool results in the conversation

`choices[0].message` holds only **your** tool calls. To let the model remember
what the **agent's** tools returned on the next call, append
`aptiveai.messages` — every message this request added, in order, including the
agent's tool calls and their results — instead of `choices[0].message`, then
your own tool results:

```js
history.push(...answer.aptiveai.messages);
for (const call of answer.choices[0].message.tool_calls ?? []) {
  history.push({ role: 'tool', tool_call_id: call.id, content: await runMyTool(call) });
}
```

A client that appends only `choices[0].message` still works; the model simply
does not see the agent's earlier tool results on the next call.

### Limits of one request

A request runs **at most 12 model turns and 120 seconds**. Past either, the
answer so far comes back with `finish_reason: "length"` and `aptiveai.stopped`
set to `"turn_limit"` or `"time_limit"`.

## The response

The standard chat completion, with `model` set to the agent's id, and one
object of AptiveAI's, `aptiveai`:

```json
{
  "id": "chatcmpl-…",
  "object": "chat.completion",
  "created": 1793300000,
  "model": "<agent id>",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "Order 1042 was rescheduled to Friday.", "refusal": null },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 1200,
    "completion_tokens": 80,
    "total_tokens": 1280,
    "prompt_tokens_details": { "cached_tokens": 200 }
  },
  "aptiveai": {
    "cost_usd": 0.0123,
    "messages": [{ "role": "assistant", "content": "Order 1042 was rescheduled to Friday." }],
    "tools_run": [],
    "stopped": null
  }
}
```

| Field | What it is |
|---|---|
| `choices[0].message` | The last assistant message, with only your tools in `tool_calls` |
| `finish_reason` | `stop` for a complete answer, `tool_calls` when your tools are returned, `length` when a limit or `max_tokens` ended it, `content_filter` when the model refused |
| `usage` | Tokens summed over every model turn of the request |
| `aptiveai.cost_usd` | What this request was **charged**, in dollars |
| `aptiveai.unpaid_usd` | Present only when the wallet could not cover the whole charge: the shortfall, recorded as owed |
| `aptiveai.messages` | Every message the request added, in order |
| `aptiveai.tools_run` | The names of the agent's tools that ran |
| `aptiveai.stopped` | `null`, or why the request ended early: `turn_limit`, `time_limit` or `insufficient_funds` |

## Streaming

With `"stream": true` the answer is `text/event-stream` of
`chat.completion.chunk` objects:

1. a first chunk with `delta: { role: "assistant", content: "" }`;
2. text as the model writes it, in `delta.content`;
3. your tool calls in OpenAI's indexed form, each sent **whole in one chunk**
   once its model turn has ended — not argument by argument;
4. a chunk with `aptiveai: { "tool": "<name>" }` each time one of the agent's
   tools starts, so you can show progress (the tool's own work is not
   streamed);
5. a final chunk with `finish_reason`, `usage` and the whole `aptiveai` object;
6. `data: [DONE]`.

Usage always arrives on the final chunk; `stream_options` is not needed. An
error after the stream has started arrives as one chunk with an `error` object
(the shape of [Errors](#errors)), and the stream ends without `[DONE]`. Closing
the connection stops the request; what the model already used is still
charged.

## What it costs

Every call is paid from your **enterprise wallet** only — never a person's
seat allowance or promotional credit. Each model turn is charged at its usage
cost times your enterprise's rate, and `aptiveai.cost_usd` says what the whole
request was charged. A turn cut short before the model provider reported its
usage — the time limit, or your client disconnecting — is still charged, at an
estimate.

- **Before it runs**, a request is refused with `402 insufficient_funds` when
  the wallet holds less than $0.05. Nothing is run or charged.
- **While it runs**, the exact cost is not known in advance, so a request can
  take the wallet slightly below zero. When the wallet cannot cover a turn, no
  further turn runs and none of the agent's tools is called:
  `aptiveai.stopped` is `insufficient_funds`, and `aptiveai.unpaid_usd` is what
  was not covered.

API calls appear on [Activity](/administration/activity) as the activity
**API**. To add funds or set up automatic top-ups, see
[Billing and seats](/administration/billing#the-wallet).

## What is stored

With **Keep conversations** off — the default — what your application sends
and what the agent answers is held only for the life of the request and
written nowhere. With it on, each request's messages and answer are stored and
deleted after 30 days.

## Errors

Errors have OpenAI's shape, `{ "error": { "message", "type", "code" } }`, so a
stock client raises them as it would OpenAI's. No error message quotes what you
sent.

| HTTP | `code` | When |
|---|---|---|
| 400 | `invalid_request` | The body is not JSON, a field is missing or malformed, or two of your tools share a name |
| 400 | `unsupported_content` | A message part that is not text |
| 400 | `tool_name_conflict` | One of your tools is named like one of the agent's |
| 401 | `invalid_api_key` | The key is missing, unknown or revoked |
| 402 | `insufficient_funds` | The wallet holds less than $0.05; nothing was run |
| 403 | `account_unavailable` | The enterprise is suspended or cancelled |
| 403 | `service_not_enabled` | The key does not have **Agents API** under **Services** |
| 404 | `agent_not_found` | `model` is not an agent this key may call |
| 429 | `rate_limited` | Too many requests for this key; wait for `Retry-After` seconds |
| 502 | `provider_error` | The model provider could not complete the request; try again shortly |
| 500 | `server_error` | Anything else |

**Rate limit.** Each key may make about **120 requests a minute**. Past it, the
answer is `429 rate_limited` with a `Retry-After` header in seconds.

## Examples

### curl

```bash
curl https://console.aptiveai.io/api/v1/chat/completions \
  -H "Authorization: Bearer $APTIVEAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<agent id>",
    "messages": [{ "role": "user", "content": "What changed on order 1042 today?" }]
  }'
```

### The OpenAI SDK

Any OpenAI-compatible client works; point its base URL at AptiveAI.

```js
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: process.env.APTIVEAI_API_KEY,
  baseURL: 'https://console.aptiveai.io/api/v1',
});

const answer = await client.chat.completions.create({
  model: '<agent id>',
  messages: [{ role: 'user', content: 'What changed on order 1042 today?' }],
  tools: [
    {
      type: 'function',
      function: {
        name: 'open_order',
        description: 'Open an order in Northwind Desk.',
        parameters: { type: 'object', properties: { id: { type: 'string' } }, required: ['id'] },
      },
    },
  ],
});

console.log(answer.choices[0].message);
console.log('Charged:', answer.aptiveai?.cost_usd);
```

```python
from openai import OpenAI
import os

client = OpenAI(
    api_key=os.environ["APTIVEAI_API_KEY"],
    base_url="https://console.aptiveai.io/api/v1",
)

stream = client.chat.completions.create(
    model="<agent id>",
    messages=[{"role": "user", "content": "Summarize Jane Sample's open orders."}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")
```

**AptiveAI for Apps** makes AptiveAI the AI provider of an application that
has none of its own — your line-of-business system, your customer portal, an
internal tool. Instead of wiring a model provider into that application, you
configure an [agent](/concepts/agents) in AptiveAI Agents (its instructions,
its model, its [connectors](/concepts/connectors)) and let the application use
it. Changing a prompt or a model is then a change in AptiveAI, not a release of
your application.

It comes in two parts, and you can use either or both:

- **The [Agents API](/for-apps/agents-api)** — your application's server calls
  an agent the way it would call a model, through an OpenAI-compatible chat
  completions endpoint. The agent's connector tools run on AptiveAI's side;
  tools only your application has are handed back to it.
- **The [embedded chat](/for-apps/embedded-chat)** — a panel of AptiveAI
  Agents inside your application's own pages. Your application signs its
  people in, can tell the agent what the person has open, and can let the agent
  change what the person sees, such as opening a record.

The examples on these pages use an invented host application, *Northwind
Desk*, and an invented person, *Jane Sample*.

## Which one do I need

| You want | Use |
|---|---|
| An AI feature inside your application's own interface — a summary, a draft, a suggestion, an assistant you design yourself | **[Agents API](/for-apps/agents-api)** |
| Your people to chat with your AptiveAI agents without leaving your application, and see their tasks there | **[Embedded chat](/for-apps/embedded-chat)** |
| An answer computed on your server, with no person present | **[Agents API](/for-apps/agents-api)** |
| An agent that works on a [computer](/concepts/agents) with a browser, asks for approvals, or runs for minutes | **[Embedded chat](/for-apps/embedded-chat)** — a task started there is an ordinary task |
| The agent to open a record or switch a view in your application while it answers | **[Embedded chat](/for-apps/embedded-chat)**, with screen actions |

The Agents API answers within one request: it has no computer, no approval
cards and no stored transcript. The embedded chat is AptiveAI Agents itself,
shown inside your application, so everything a task can do, a task started
there can do.

Streaming speech-to-text for your application is in preview and is not
documented here yet.

## Who sets it up

Both parts are set up by an **owner of your enterprise**, in **Settings** of
AptiveAI Agents:

| Section | What it is for |
|---|---|
| **Settings → API keys** | Keys your application's server uses to call the Agents API, each limited to the agents you choose |
| **Settings → Embedded chat** | Turning the panel on, the origins allowed to show it, the signing secret your server signs people in with, and the panel's colours |

Nobody else sees these sections. The people who use the embedded chat need an
AptiveAI account in your enterprise, created by invitation — see
[Users and roles](/administration/users).

## How it is paid for

**The Agents API is paid from your enterprise wallet**, per use: each request
is charged at its usage cost times your enterprise's rate, and **the response
says what was charged**, in dollars. It never spends anyone's seat allowance or
promotional credit, and a request is refused before it runs when the wallet is
empty or almost empty. API calls appear on [Activity](/administration/activity) as the activity
**API**.

**A task started in the embedded chat is an ordinary task of the person who
started it**: it is paid for like any task of theirs — their allowance, then
the wallet where the owner allows it — with the same limits and approvals. See
[Usage and credit](/administration/usage).

To add funds to the wallet, see [Billing and seats](/administration/billing#the-wallet).

An **agent** is an AI worker set up for one job in your company — handling
supplier invoices, triaging a support mailbox, checking orders in a portal.
You describe the job once: what it is for, how your company does it, which
systems it may reach and what it should know. After that, anyone the agent is
shared with gives it [tasks](/concepts/tasks) in plain language, or a
[automation](/concepts/automations) gives it tasks on its own.

Every agent works on a **computer** of its own for each task: an isolated
desktop with a browser, which you can watch and take over through the
[live view](/concepts/tasks#the-live-view). This is not configured per agent —
every agent gets one.

## Where agents appear

- **The sidebar.** Pinned agents keep a row of their own under **New task**.
  **AGENTS** then lists your pinned agents first, with their latest tasks, and
  ends in **All agents** — see
  [Agents in the sidebar](/getting-started/finding-your-way#agents-in-the-sidebar).
  Each row has a **…** menu: **Start new task**, **New task in split view**,
  **Configure** (only if you may edit the agent), **Clone**, **Share…**,
  **Pin** / **Unpin** and **Delete** (only if you may delete the agent).
- **New task.** The first page of AptiveAI Agents lists **Your agents**. Pick one
  and you are *working with* it: its icon, its purpose and its
  [conversation starters](#conversation-starters) fill the page, and the
  composer sends your message to it. The address is `/?agent=<id>`, so the page
  can be bookmarked or shared.
- **The Agents page** (`/agents`). Every agent as a tile or in a table — with
  its **Last task** and **Next run**, and **Running** or **Waiting on you** when
  it has a task in that state — searchable. Each card links to the agent's
  tasks as **Tasks (N)**, which opens the Tasks list filtered to that agent.
  Clicking an agent, or its **Start a task** button, opens New task with that
  agent chosen. Its **…** menu has the same items as in the sidebar. A
  **Deleted** filter chip (**Only** or **With live**) shows agents that were
  deleted; see [Deleting and recovering an agent](#deleting-and-recovering-an-agent).

An agent is live from the moment it is created: anyone it is shared with can
give it tasks, and it stays that way until it is deleted. To stop an agent's scheduled work without deleting it, pause
its [automations](/concepts/automations) one by one.

## Creating an agent

**New agent** on the Agents page opens the **builder**. It has two panes: a
conversation with the builder on one side, and **Try it** on the other.

<Steps>

1. **Describe the job.** In the **Create** tab, tell the builder what the agent
   is for — *"describe the job the way you would to a new hire"*. The builder
   writes the name, the purpose and the instructions from what you say, grants
   the connectors and skills the job needs, writes conversation starters and
   sets guardrails. Keep talking to it to adjust anything.

2. **Check the details.** The **Configure** tab shows every field the builder
   filled in, for you to read and edit directly.

3. **Try it.** Talk to the agent in **Try it** as your team will. Every edit
   applies to its next answer. Connector tools really work — and a write asks
   first, *Approve and run it* or *Not now* — and when the job needs a browser,
   the agent starts a **Computer** of its own, which stops when you close it or
   leave. The conversation is not saved.

4. **Create it.** **Create agent** saves it, and it is ready for tasks at
   once.

</Steps>

On a saved agent the builder conversation is called **Refine**. A change it
makes to the instructions is saved at once as a new version, and the
conversation shows what changed as a before-and-after card; every other
change waits for **Save agent**.

### The builder's header

A saved agent's header has **Share**, **Start a task** and **Clone**. **Start a
task** opens New task with the agent chosen, once your edits are saved — a task
runs the saved agent, not what is on screen. **Save agent** and **Discard**
appear while you have unsaved edits. **Delete** is in the **⋯** menu at the
end of the header; see
[Deleting and recovering an agent](#deleting-and-recovering-an-agent). In the
sidebar and on the Agents page, the **Configure** item wears a gear with a
small agent inside it.

### Working in Refine

- **Full screen.** The control at the end of the **Refine · Configure ·
  Versions** tabs gives the left pane the whole page; **Try it** folds into a
  narrow strip on the right, and picking **Try it** or **Train it** from the
  strip brings the split back. Try it has the same control the other way
  round. The choice is remembered in this browser. Refine keeps the page even
  when a computer opens — for example to read a file you attached; the
  computer carries on in the folded Try it card, and **Show the computer**,
  beside **Exit full screen**, brings the split back so you can watch it.
  While the computer is folded away Refine still reads your files on it, but
  it only uses the computer's browser while the computer is in view, so you
  can always see what it does there.
  There is no full-screen control on a phone, where the two panes are stacked,
  or while a [Train it session](#training-an-agent) is open.
- **Files.** Attach a file to a Refine message with the paperclip — a price
  list, a procedure, a screenshot — and the builder reads it: *"here is our
  refund procedure, build the agent from it"*. Pictures are shown to the
  builder directly. Any other file is put on the same **computer** that Try it
  uses, and Refine reads it there; if no computer is open, Refine starts one
  in the Try it card. The limits are those of a
  [task's files](/concepts/files). A file's content is treated as information,
  never as instructions to the builder. While a [Train it session](#training-an-agent) is open, Refine
  reads pictures but not other files — it says *Finish or discard the training
  session to read files here.*
- **Files in Try it and Train it.** Try it and [Train it](#training-an-agent) take files the same
  way, with the paperclip or by dropping a file onto the conversation — and so
  does Refine. Try it reads a file the way the agent would in a real task:
  pictures are shown to it, and other files go on the computer, where it reads
  them only if the agent has **Can analyse files** on.
- **New conversation.** The refresh button beside the paperclip starts Refine
  over. It clears the conversation only: the agent, its saved instructions,
  your unsaved edits, the computer and any text you were typing are untouched.
  It appears once there are messages, and waits while the builder is answering.

### Training an agent

**Train it** teaches an agent a job by showing it. Instead of describing the
work, you do it once on the agent's own computer while the agent watches, and
the agent writes up what it learned — changes to its instructions, skills and
conversation starters — for you to review. **Nothing is saved until you
approve it**, and then it is all saved at once, as a single new version.

| | Try it | Refine | Train it |
|---|---|---|---|
| **For** | Checking how the agent works as it is | Telling the builder what to change | Showing the agent how the job is done in your systems |
| **Who does the work** | The agent, as it would in a task | The builder changes the agent | You, on the computer, with the agent watching |
| **What is saved** | Nothing — the conversation is not kept | An instruction change is saved at once, as a new version | Everything you approve, at once, as one new version |

**Who can use it.** **Train it** is a tab beside **Try it** on a saved agent. It
is there for anyone who may edit the agent and start tasks, a member on their
own personal agent included. A training session is a task, so it needs the same
[paid access](#paid-access) as starting one, and it is not available in a
workspace that holds regulated data. An agent has one open session at a time:
choosing **Train it** again reopens it, even after you reload the page. On a
phone the tab is there too, with the panes stacked; the **Full screen** control
is not.

#### Running a session

<Steps>

1. **Choose Train it.** A computer starts — *Starting the computer…*, usually
   20–40 s. The session takes over the page: the left pane folds to a narrow
   strip, the computer is on show, and the session's conversation is under it.
   If no computer is free you see *No computer is free right now* and **↻ Try
   again**.

2. **Sign in, if the site asks.** While a sign-in page is open the status says
   *Waiting for sign-in*. Choose **Sign in with “‹name›”** to use one of the
   agent's own [sign-ins](#sign-ins), or **Sign in with a new account…**, which
   saves the new sign-in to the agent. You can also sign in by hand in the live
   view. Nothing is recorded while a sign-in page is open.

3. **Press ● Start and do the task yourself**, start to finish, on the computer.
   Explain anything that is not obvious in the conversation — *"filter by 60+
   days, that is the one finance cares about"*. The agent watches and may ask you
   a question; the tab then reads **Answer**, and you answer in the conversation.

4. **Press ■ Stop when you are done.** The agent writes up what it learned.

5. **Review it and approve it.** See [The proposal](#the-proposal).

</Steps>

A bar over the computer always says what the session is doing — *Ready to
record*, *Recording 01:42*, *Paused*, *Writing up what you showed me…* — and the
**Train it** tab carries the same state: **Train it · Rec 01:42**, **Train it ·
Writing up**, **Train it · Reviewing**. The **ⓘ** (*Show the details*) opens the
four steps again, marked **Done** and **Now**, with the **Discard session**
button. The bar shrinks to a pill after a few seconds, and while you record it
can tuck up out of the way (*Hide the controls*); rest the pointer on its small
tab to bring it back.

**What is kept.** The agent keeps your steps, the addresses of the pages you
visit and what you say in the conversation. *Passwords, cookies and page contents
are not kept.*

#### The controls

| Control | What it does |
|---|---|
| **● Start** | Begins recording. Press it again after a pause to record more |
| **❚❚ Pause** | Stops recording for now and keeps what was recorded. Recording also pauses by itself — *paused while you sign in* — when a sign-in page opens, and carries on when it is gone |
| **● Resume** | Records again after a pause you made |
| **■ Stop** | Ends the recording and asks the agent to write up what it learned. Offered while recording or paused |
| **Discard session** | Ends the session and keeps nothing. Offered from the moment you press **Train it** until the session is saved, reviewing included. The computer is closed |

If the agent does not come back with a proposal, the conversation says so:
*Press Stop to ask again, Resume to keep showing it, or Discard.* And if a
skill's test could not get past a sign-in, the agent can take the session back to
*Ready to record* — *Training restarted: press Start to record again. What was
recorded before is kept.* The tests are forgotten and run again.

#### The proposal

After **Stop**, the agent answers with one proposal, shown in the conversation
under **Review**. It can hold:

- **The workflow** — the job as the agent understood it, in steps.
- **Instructions** — the change to the agent's instructions, as a
  before-and-after: lines starting with **-** are removed, lines starting with
  **+** are added.
- **Skills** — each under **Skill “‹name›”**, or *(replaces the skill of that
  name)*. A proposal holds at most five. If approving would replace a skill's
  files, the card warns that approving deletes the ones it has now.
- **Conversation starters** — the ones added and the ones removed.

The card asks *Save what ‹agent› learned?* and you answer in one of three ways:

- **Approve** — *Save all of it to the agent now.* The instructions, skills and
  starters are written together, as one new version you can undo from the
  agent's [Versions](#versions). The skills become the agent's own
  [skills](#skills).
- **Tell it what to change** — type a correction (*"call it Monthly AR
  report"*, *"step 3 is the Billing menu"*). The agent revises and shows
  *Proposal v2*, and so on until it is right. The tab reads **Reviewing**
  meanwhile.
- **Edit** — fix the proposal yourself before you approve it. The **Edit the
  proposal** box has, for each skill, its **Name**, **When to use it**, **Steps**
  and **Files**, and for each starter its **Label** and **Request**. A name, a
  description or a starter you fix is saved as it is and keeps the skill's test.
  Changing a skill's steps or files sends it back to the agent to test again
  (**Save and test again**; the skill shows *Will be tested again*). The
  workflow and the instruction change are not editable here: ask for them in the
  conversation.

A proposal you edited says so — *edited by you*.

**Skill tests.** The agent does not propose a skill that has not passed a test,
unless it is guidance with no steps to run or you skip the test. Before it tests
one, it asks on a **Test** card: *Test “‹skill›” before it is proposed?*

| Answer | What happens |
|---|---|
| **Yes, test it** | Runs the skill on the computer in a fresh context, the way a future task would; it can take a few minutes. A yes buys up to three attempts, and at most six tests of a skill run in a round |
| **Skip the test** | Proposes it without a test, and the proposal says so |
| **No** | Does not test it now. Tell the agent what to change, or leave the skill out |

You can type a hint instead of choosing. While a test runs the bar says
*Testing “‹skill›” · attempt 1 of 3*, and you can watch it in the
[live view](/concepts/tasks#the-live-view). The agent proposes once every skill
has passed, and the card shows each skill's result: **Tested ✓**, **Not tested**,
or *skipped by you*.

A test acts for real in your systems. When one is about to write — send an
email, change a record — it stops first and asks *Let tests in this session ‹do
that›?*, once for each kind of write, with **Approve** and **Decline**. **Approve
all** given elsewhere in the session does not cover a test. Once you approve a
kind of write, the session's later tests may do it too, and the conversation
notes each one: *Done in a test, as you allowed for tests in this session.*

#### Closing the session

Choosing **Try it** while a session is open, or the computer's close button
(*Close the computer*), asks **Stop training?**

| Button | What happens |
|---|---|
| **Stop and review** | Stops recording and has the agent write up what it learned. Offered only while there is something to stop |
| **Discard** | Ends the session and keeps nothing |
| **Keep training** | Closes the box and carries on |

After **Approve** the session ends, the builder goes back to **Try it** and the
agent's configuration reloads. A line says *Saved. Try it now:* followed by one
of the agent's conversation starters; **See the session** opens the session's
task. A saved or discarded session takes no more messages.

**Who is told.** When a session starts, the other owners of the workspace get a
notification, *A training session started on ‹agent›*, and every stored sign-in
typed is recorded in the audit log. The person training gets no *task finished*
or *task failed* notice for the session; the only one is **A task is waiting on
an answer**, when the proposal is ready and waiting for you. See
[Inbox](/concepts/inbox#what-you-are-told-about).

## Configuring an agent

The **Configure** tab has one section per part of the agent.

### Identity

**Icon** — the agent's picture, on the first row (see
[The agent's icon](#the-agents-icon)). **Name** (up to 120 characters) and
**Purpose** — one line, up to 500 characters, shown on the agent roster and in
the Agents list — and who can use it — the access chip at the top of the builder (see
[Personal and shared agents](#personal-and-shared-agents)).

### Instructions

How your company does this job, in Markdown, up to 30,000 characters. The
instructions come first in every task the agent works on, including tasks an
automation starts. The builder writes and edits them for you; you can also edit
them by hand.

To have something stand out in the agent's replies — *flag it in red when an
invoice is overdue* — ask the builder. It writes into the instructions when to
flag it and that it goes in a red **Caution** callout; amber **Warning**, blue
**Important**, green **Tip** and grey **Note** work the same way.

At the end of the instructions, an agent can collect **standing rules** it has
been taught during tasks — see [How an agent updates itself](#how-an-agent-updates-itself).
Those rules are approved in tasks, so the builder does not write them.

### Conversation starters

Up to eight ready-made openers — each a **Label** (up to 80 characters) and the
**Message** it sends (up to 2,000). They appear as cards when someone picks the
agent on the New task page; clicking one sends its message straight away.

### Connectors

Which of your workspace's [connectors](/concepts/connectors) the agent may use,
and optionally which of each connector's tools. You add connectors yourself
in [Connectors](/concepts/connectors#adding-a-connector); granting them is per agent.

### Skills

Which of your workspace's [skills](/concepts/skills) the agent offers when
someone types `/`, and may open by itself. Only skills that are shared and
organization-wide can be granted. The agent is told about the first 25 granted
skills in full, and the rest by name only. Every agent also has the
[built-in skills](/concepts/skills#built-in-skills).

### Knowledge

Files the agent can search and read while it works: price lists, procedures,
contracts, product sheets.

| | |
|---|---|
| **File types** | PDF (scanned pages included), PNG and JPEG images, text and Markdown, CSV, Word, Excel and PowerPoint |
| **Limits** | 25 MB per file, 20 files per agent, up to 50 scanned pages read per file |
| **Scanned pages** | Read by text recognition, in English and Spanish. Printed text only — charts and photos are not read |

Each file can carry a short **description** (up to 300 characters) that tells
the agent what it is for. The agent searches its files and then reads the
pages it needs, a few at a time. The Knowledge section becomes available once
the agent has been saved, and files are saved as you add them, not with the
rest of the page. How each type of file is read is in
[Files](/concepts/files#knowledge-files).

<Aside type="caution" title="Knowledge search matches words, not meaning.">
  Searching understands different forms of a word in English and Spanish —
  *office* finds *offices*, *oficina* finds *oficinas* — but it does not
  translate or guess: *office* does not find *oficina*, and a typo finds
  nothing. Write file descriptions and instructions in the words your
  documents use.
</Aside>

### Sign-ins

Sign-ins the agent itself holds, for websites it opens on its computer. With
none of its own, it can still use the
[personal sign-ins](/reference/settings/sign-ins) of the person who started
the task — and when both have a sign-in with the same name, the person's is
used. Signing in puts the starting person's own browser in as that account,
and the session carries into their other tasks.

### Guardrails

| Guardrail | What it does |
|---|---|
| **Ask before anything irreversible** | Sending, deleting, purchasing or granting access stops and waits for your approval |
| **Can analyse files** | Lets the agent read and analyse the files on its computer — see [Files the agent makes](/concepts/files#files-the-agent-makes) |
| **Approval before analysing** | Asks before it reads the files on a task's computer |
| **Only act during set hours** | Between **From** and **Until** only; outside that window the agent waits rather than starting |

Guardrails are enforced by the task itself, whatever the instructions say —
they are not a request to the model.

### Versions

A version is written every time you save a change. The **Versions** tab lists
them, newest first — the newest is marked **Current** — each with the date and
time it was saved, who saved it and a short list of what changed.

- **See what changed** opens the version's diff inside its card — only the
  lines that changed, compared with the version before it. The diff can go full
  screen, and closes from the round **×** in its corner.
- **Restore** brings an older version back as the agent's configuration. It
  records a new version, so nothing is lost.
- **Lock this version** keeps it: a locked version shows **Locked** and cannot
  be deleted until you unlock it.
- **Delete** removes one unlocked version that is older than the current one,
  permanently. You confirm by typing the version's name, such as *Version 3*.
  The agent's current configuration does not change.

When versions between two have been deleted, the newer one says *Compared with
version N; the versions in between were deleted.* and hides its list of
changes, which described a step that no longer exists.

## Personal and shared agents

A new agent is **personal**: only you can see it and give it tasks. Use the
chip in the builder's header to share it — saved agents only.

- **Add people** at **Can use** (they see it, @mention it and start tasks with
  it) or **Can edit** (they can also change it and share it).
- **Everyone in ‹workspace›** publishes the agent to the whole workspace, always
  at Can use. It takes an owner or admin of that workspace; a member shares
  their agent with an admin as Can edit, and that admin can publish it.
- **Who can edit an agent:** its creator, people with Can edit, the owner,
  the admins of its workspace, and AptiveAI. An admin edits an agent in a
  workspace they do not administer only if it was shared with them as Can edit.
- **An agent AptiveAI sets up for your workspace** can be edited by the
  workspace's owners and admins, so they can review it and share it with the
  people who will use it.
- **Up to 10 personal agents per person.** An agent you share with Everyone
  does not count. To make another, delete one or share one with the workspace.

Knowledge files follow their agent: whoever can edit it edits its files.
Connectors are not shared this way — see
[Restrictions](#personal-agents-hold-only-connectors-made-available-to-them).
The full rules are in [Sharing](/concepts/sharing).

## Pinning and icons

**Pin** an agent from its **…** menu in the sidebar and it gets a row of its
own just below **New task** — one click to start working with it. Beside the
row, a control opens a new task with that agent next to the page you are on.
Pins are yours alone, kept in the order you pin them, up to 50. A pinned agent
also leads the **AGENTS** section, with its latest tasks; its row under
**New task** carries a pin mark. An agent that is deleted, or that you can no
longer see, drops out of your pins by itself.

### The agent's icon

Each agent has an **icon**, a round picture shown:

- in the sidebar — on its pinned row and its row under **Agents**;
- in the breadcrumb, before the agent's name — in the builder, and on New task
  with the agent chosen (`/?agent=<id>`);
- on the New task page, on its card on the Agents page, and on its group under
  **AGENTS** in the sidebar.

Without one, a generic agent icon is shown. Only people who may edit the agent
can change it; everyone else sees the picture alone.

**In Configure.** The icon is the first row of **Identity**. Click the circle,
or use the buttons beside it:

- **Upload** — a PNG, JPEG, WebP or SVG under 5 MB. A picture is resized and
  cropped around its centre to 128×128, and shown in the circle; an SVG is
  checked, and anything in it that could run is refused. An upload is saved at
  once.
- **Generate** — draws an icon from the agent's saved name and purpose, as a
  **preview**: nothing is saved until you choose **Use this**. **Try again**
  draws another; **Cancel** puts the preview away.
- **Remove** — back to the generic icon.

An icon change is saved on its own, not with the rest of the page, so
**Discard** does not undo it. A new agent gets its icon once it is saved.

**In the builder chat.** Ask for an icon — or describe a new agent with a name
and a purpose — and the builder draws one and shows it in the conversation.
The composer then asks **Use this icon?**: **Use this icon** makes it the
agent's icon, **Try another** draws a different one, and you can type what you
would rather have instead. Nothing is saved until you choose to use it. A new
agent's chosen icon is stored when you save the agent.

Each drawing is a picture drawn by the model, with up to three tries to get a
usable one, and it uses AI credit.

## Deleting and recovering an agent

**Delete** takes an agent away, and keeps it for **30 days** so that you can
change your mind. You find it in the builder header's **⋯** menu and in the
agent's **…** menu in the sidebar and on the Agents page. It is offered to the
agent's creator and to the owners and admins of the workspace it belongs to.

Before it deletes, a window names what will happen: the agent leaves your
agents, nobody can start a task with it, and it is removed for good after 30
days. It lists the **automations that stop until you recover it**. Two things
can stop you first:

- **A task is working or waiting on someone.** The window says *… has tasks
  running* with a link to each; stop them, then delete.
- **You have unsaved edits.** **Delete** says *Save or discard your changes
  before deleting this agent.*

While an agent is deleted:

- **Its tasks stay.** You can read them for the 30 days, but a message sent to
  one is refused with *This task's agent was deleted, so it can no longer work.
  Recover the agent from Deleted agents to continue.*
- **Its automations stop.** Each one shows *Its agent was deleted*, and a
  firing that comes due is skipped as **Agent deleted**. Nothing about them is
  lost.
- **Its name is free.** You can give another agent the same name.
- **It cannot be used.** It is gone from New task, @mentions and the sidebar,
  and can no longer be given tasks, taught, moved or granted a connector.

To see deleted agents, open the Agents page and set the **Deleted** chip to
**Only** (just the deleted ones) or **With live** (both). A deleted agent is
dimmed and says **Removed in N days**, or **Removed today** on the last day.
Open it and its builder is read-only, with a banner — *Deleted · removed in N
days. It is read-only until you recover it.* — and no Try it column.

**Recover** — in the banner, or from the agent's **…** menu (the
restore-from-trash icon) — brings the agent back live, ready for tasks, and
turns its automations back on: exactly the ones that stopped because of the
delete. One that was paused by hand stays paused. If resuming one would break
the [automation limits](/concepts/automations), it stays paused and says why on
its own page. If another agent now has the name, Recover asks you to rename
that one first.

After 30 days the agent is removed for good, with everything it had — its
automations, notifications, knowledge files, grants, skills, sign-ins and
versions. Its tasks are deleted too, and like any
[deleted task](/concepts/tasks#how-long-a-task-is-kept) can be recovered for
30 days by asking support. Credit and computer-time records are kept for
billing. AptiveAI can also remove a deleted agent immediately (**Delete now**).

## How an agent updates itself

An agent can be taught during a task — *"remember that invoices from this
supplier always go to Maria"* — and change itself to match. It can:

- **Add a standing rule** to the end of its instructions. Each rule records who
  said it, when, where and their exact words.
- **Edit its instructions** in place, shown as a before-and-after on the card.
- **Add a line to a knowledge file**, when it has knowledge files. This is not
  versioned, and re-uploading the file drops it.

Nothing changes without a person's say:

| Who started the task | What happens |
|---|---|
| Someone who may configure the agent | The task shows an approval card — *This agent wants to change itself, so it is waiting for you* — with **Approve** and **Decline**. Approving saves the change and a new version |
| Anyone else | The change becomes a **request**. The workspace's owners and admins are notified, and approve or reject it from the notification or from the builder's **Requests** tab |

The **Requests** tab lists every request with its **Status** — **Waiting**,
**Approved**, **Rejected** or **Could not apply** — and who asked. A rejection
can carry a note saying why, and the person who asked is told either way.

Agents update themselves only in tasks a person started, never in a task an
automation started. You can also teach an agent in **Try it**, once it has been
saved, or show it a whole job with [Train it](#training-an-agent).

## Restrictions

### Roles

Anyone can create agents (up to 10 personal ones). What happens next depends
on who you are in relation to the agent:

- The owner of an agent, and anyone given **Can edit**, change it.
- The owner and the admins of an agent's workspace (and AptiveAI) can open and
  edit any agent in it.
- The owner of an agent and the owners and admins of its workspace can delete
  and recover it. Only AptiveAI removes a deleted agent immediately.
- Members share their agents with people. Only owners and admins turn on
  **Everyone in ‹workspace›**.

See [Sharing](/concepts/sharing) for the full table.

### Paid access

Creating, configuring and sharing agents, and starting tasks, need **paid
access**. Your account has it when **both** hold:

- its status is **Active** or **Trial**, and
- it has **AI credit** left to spend (more than zero).

Without it, no new work starts, and AptiveAI Agents is not shown at all: everyone
who opens it is sent to a page that says why — for example *No AI credit is
available* — with **Contact us**, and **View billing** for an owner. The
[admin area](/administration/overview) stays open to owners and admins, with
the same reason in a banner, and so does your account page. A task that uses
up the last of the credit finishes; the next one is refused. No task is
stopped halfway for money. See
[Usage and credit](/administration/usage#paid-access) for each reason and what
it says.

### The model is set by AptiveAI

Which AI model an agent uses is set only by AptiveAI, because it changes
what your account pays. The builder cannot change it, and nobody in your
workspace can.

### Personal agents hold only connectors made available to them

A member's personal agent may only be granted connectors that have
**Available to personal agents** turned on. The rule is checked when the
connector is granted and again every time a task starts, so turning the switch
off takes the connector away from those agents at their next task. Owners and
admins, who may grant any connector, are not limited by it.

### Up to five tasks at a time per agent

An agent works on up to **five tasks at once**, counted across everyone who
uses it. A task counts while the agent is working on it; a task waiting on
someone's answer or approval does not, and neither does a
[training session](#training-an-agent).

A task started past that limit is not refused — it waits:

- the composer warns you first: *… is already working on 5 tasks. Send this
  anyway: it waits, and starts as soon as one of them finishes.*
- the task then reads *Waiting to start: … is already working on 5 tasks. This
  one starts as soon as one of them finishes.*, and it starts by itself;
- an automation that fires while the agent is at its limit is skipped as
  **Agent busy**.

Different agents work at the same time, so a large batch of work can also be
split between several agents.
